## Layout, responsive, and scrolling audit

- Sidebar scrolling is applied to `.chat-sidebar`, which works technically, but it scrolls the search bar and divider along with all lists. The unused `.chat-sidebar-content` indicates the intended structure was likely a padded, independently scrollable content section.
- `SearchBar.jsx` correctly uses `.chat-search`, but without the missing sidebar content wrapper it has no surrounding spacing.
- `.conversation-body` is the correct primary message-scroll container and correctly has `overflow-y: auto`.
- `messages-container` has `min-height: 100%`, which makes empty-state centering work, but message layout would be more robust if the surrounding flex layout explicitly allowed its scrolling child to shrink. The fixed viewport page height and mobile sidebar height make this more noticeable on short screens.
- At `max-width: 700px`, the page becomes a fixed-height vertical split with a fixed `280px` sidebar. This may leave limited conversation space on short mobile viewports; there is no mobile-specific adjustment for the header, input area, or sidebar content.
- The message input is outside `.conversation-body`, which is structurally correct for a fixed composer, but because it does not use `.chat-input-area`, it lacks the intended top border and stable visual separation.
- User cards and recent-chat cards use the correct card/header/name/time/preview classes. Recent cards lack only the selected-state class.
- The online indicator is correctly wired: both `UserList.jsx` and `RecentChats.jsx` render `online-dot` plus either `online` or `offline`. The indicator’s base, online, offline, and pulse CSS all apply.
- Message bubbles, author, content, metadata, timestamps, typing indicator, search bar, user cards, conversation header, and recent chats use their currently intended active CSS classes. The main exception is sent-bubble styling: it works through the parent descendant selector rather than the unused `.message-bubble.mine` selector.
- Timestamps have no dedicated class; they inherit formatting through `.message-meta`. This is consistent with the existing CSS, though individual timestamp styling is not possible.

## Inline styles that duplicate available chat CSS

`form-actions` and the button styles come from the global theme, not `chat.css`.
